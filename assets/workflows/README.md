# تحريك بالذكاء الاصطناعي (صورة ← فيديو) — اختياري

بدون هذا الملف يعمل المشروع كاملاً: كل لقطة تُحرَّك في بلندر (كاميرا، تأثيرات ثلاثية الأبعاد، عيون، مونتاج).
هذه الطبقة الاختيارية تجعل **لقطات البطولة** (الضربات، القتال، اللقطات القريبة، الافتتاح) تتحرك بحركة حقيقية من نموذج فيديو،
وهي أقرب شيء لمظهر الفيديو المرجعي (Guy vs Akaza). تحتاج **كرت شاشة** في مكان ما؛ المشغّلات المجانية في GitHub لا تملك واحداً.

## التشغيل

1. شغّل ComfyUI على جهاز فيه GPU (جهازك، Colab، Kaggle، RunPod ...) وثبّت نموذج فيديو (LTX-Video أو Wan 2.x أو HunyuanVideo ...).
2. في ComfyUI ابنِ مخططك: صورة ← فيديو. ثم **Save (API Format)** وضع الملف هنا باسم `i2v_api.json`
   (أو ابدأ من `i2v_api.example.json` — **مثال لم يُجرَّب** مبني على مثال LTX-Video المنشور؛ أسماء العقد والحقول تتغير بين إصدارات ComfyUI).
3. اضبط الإعدادات (متغيرات GitHub أو `.env`):

```
I2V_BACKEND=comfyui
COMFY_URL=https://عنوان-النفق-أو-الجهاز:8188
I2V_BUDGET=6          # أقصى عدد لقطات بطولة في كل مقطع
I2V_SECONDS=4         # طول كل لقطة
I2V_NATIVE_FPS=24     # 24 لـ LTX-Video، 16 لـ Wan
```

## العناصر النائبة داخل المخطط

ضع هذه النصوص في أي حقل نصي/رقمي؛ إذا كانت قيمة الحقل **هي** العنصر النائب وحده يُستبدل بقيمة من النوع الصحيح (عدد صحيح للـ seed مثلاً):

| العنصر | المعنى |
|---|---|
| `{{image}}` | اسم الصورة بعد رفعها إلى ComfyUI |
| `{{prompt}}` / `{{negative}}` | وصف الحركة / ما نتجنبه |
| `{{seed}}` | بذرة ثابتة لكل لقطة (يمكن إعادة التوليد بنفس النتيجة) |
| `{{width}}` `{{height}}` | مضاعفات 32، الحد الأقصى للضلع الطويل 832 |
| `{{frames}}` | عدد الإطارات (8n+1) |
| `{{fps}}` | معدل إطارات النموذج |

يجب أن ينتهي المخطط بعقدة حفظ (`SaveWEBM` أو `VHS_VideoCombine` أو `SaveAnimatedWEBP` ...). يُحوَّل الناتج إلى تسلسل صور بمعدل الخط
ثم يعمل فوقه بلندر (كاميرا، تأثيرات، تدريج) والمونتاج كالمعتاد. إن لم يكن ComfyUI متاحاً وقت التشغيل تبقى اللقطة مُحرَّكة في بلندر
دون أي فشل.
